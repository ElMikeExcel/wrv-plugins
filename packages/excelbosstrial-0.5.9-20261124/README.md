## Join-armed returns (0.5.9)

`/bosstrial armreturn <player> emloot <loot-file>` arms a return for a player; `/bosstrial disarmreturn <player> [loot-file]` takes an arm back; `/bosstrial listreturns` shows what is waiting. Arming stores data only — a row in `armed-returns.dat` (player, loot file, who armed it, when; SHA-256-checksummed like the claims ledger) — so it can be done while the player is offline, and the loot file is validated against EliteMobs' registry at arm time so a bad arm can never be stored. The moment that player next joins, BossTrial's own join listener builds the item with the player present through the same EliteMobs construction `grantclaim` uses, files it into the player's `/bossrewards` claims, removes the arm, and tells the player in chat and with an on-screen title naming the item. A failed build keeps the arm for the next join and logs an `ARMED-RETURN FAILED` line; before granting, the listener checks the claims ledger for an unclaimed console-grant claim of the same item, so a crash between grant and disarm can never produce a second grant.

WHY THIS EXISTS (Mike, Nov 24, 2026): a return must be credited while the player is online, because EliteMobs applies its Soulbind only when the recipient stands in front of the construction — an offline credit is a genuine but unbound item. The first return after that rule (Jester's Alanus' Dagger) was therefore going to be fired by an outside fleet watcher polling the player list every two minutes to spot the login. Mike's ruling: Paper already broadcasts every player join to every plugin, so a job that can be done by a plugin listening to the server's own events belongs IN the plugin — returns are armed ahead of time and land the moment the player logs in, with no polling, no watchers and no tokens spent watching a screen.
