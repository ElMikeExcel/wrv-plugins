Verify the actual downloaded artifact, exact runtime behavior, temporary LuckPerms attachments, selection/operation limits and edit completion/undo before enabling the attachment. No hub-area enclosure is necessary. Source defaults remain off and nobody is eligible.
5. Capacity and diagnostics. Current allocation exceptions can leave a provider endpoint faulted after capacity returns, suppressing fresh Survival awards. This is an explicit release blocker. A separately tested typed-capacity outcome and visible refusal/retention policy is required; see CAPACITY-RELEASE-GATE.md. No shared allowed-token shortcut or silent evictions.
6. Operational approval. Verify usable coherent world/plugin/playerdata backup, host quota/headroom, rollback and private one-builder cohort setup. Obtain explicit owner approval for the exact artifacts, restart and bounded access. Retain former cohort members until recovery is verified. Activation of the completed hub as spawn is separate.

Already checked in isolation: immutable inventory/XP restoration; scoped journal/cohort failure; independent review holds; native marker commit order; disabled or silently failed player saves; entry-only storage budgets; active-session restart. These are not universal crash-atomicity or hardware-loss guarantees.

Not required for the first Java-only pilot: a new world, WorldGuard, FAWE, Bedrock form UX, a decided hub region or a broad natural-grinder policy. Same-world Creative blocks can be harvested later; the owner understands this trusted-building scope.
