## Mechanism verification (the design's load-bearing fact)

Magic 11.2.5 (`work/magic-11.2.5.jar`, sha256 `79e49fe3…`) was extracted and scanned
for a cast-confirmation facility: every "confirm" occurrence is a SelectorAction/shop
GUI option or RecallAction's `confirm_marker`; BaseSpell/Spell expose cooldown
accessors but no confirm deferral, and the cooldown is charged when a cast runs. **No
native facility exists** — hence the Together-gated lockout design (SOURCE.md).

## Unit suite (headless, run by build.sh)

**826 checks, 0 failures** = the full inherited suite (791: PartyTest 18,
PartyFeatureTest 196, RangeIndicatorTest 61, McmmoLinkTest 79, McmmoSyncTest 86,
ShareTest 30, XpShareTest 22, BaseRulesTest 100, EmSyncTest 93, EmLinkMappingTest 73,
PartyLookupTest 6, PartyRepairTest 27) plus the new **RepairGateTest: 35 checks**:

- State machine: fresh caster → ARM; verdict alone never arms or locks; arm → CONFIRM
  inside the window (verdict is read-only — still confirmable on a second read);
  confirm → LOCKED with the full cooldown remaining, counting down; per-caster
  independence; lockout ends exactly at the cooldown boundary.
- A lapsed arm costs nothing: window-edge confirm still works, one tick past it the
  verdict is ARM again with zero remaining, and re-arm + confirm works after a lapse.
- Persistence format: snapshot keeps live lockouts and prunes expired ones; restore
  reproduces the lock on a fresh gate with the same remaining time; the store's file
  round-trip is exact; missing file = clean slate; malformed keys skipped, good keys
  kept; an unreadable file loads as a clean slate without throwing.
- Texts: the prompt carries the live count, the window, and the formatted cooldown
  with no placeholders left; the zero-count prompt names the member count and states
  the burn plainly; the refusal carries the formatted remaining time; custom texts
  and values flow through; blank texts fall back to the defaults.
- `formatDuration` pins: 0 → "0s", 59s → "59s", 59.5s → "60s", 60s → "1m",
  10 min → "10m", 4h → "4h 0m", 3h12m → "3h 12m".

### Honest rig notes (two false starts, both mine, both fixed before the passes above)

1. The first boot-A attempt reported ARM/CONFIRM failures — root cause was **rig
   contamination, not the build**: the rig server was cloned from build-0.5.1's rig
   including Magic's per-mage data, so the fake players carried a live 4-hour Magic
   cooldown from the 0.5.1 runs (remaining 12,380,535 ms at first read) and Magic
   refused every cast before the gate ever saw it (no gate lines in that log at
   all). Cleared `plugins/Magic/data/players/*.dat*` and re-ran clean — the passes
   above are from the clean run.
2. The first driver draft fetched each mage's spell during setup; `getSpell`
   returned null that early (the 0.5.1 driver fetched inside its phases for this
   reason). Fixed to lazy per-phase fetch before the clean run.
