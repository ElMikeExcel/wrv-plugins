## Judgment calls (for the record)

1. **Confirm-target union for `teleport_confirm_spawn`**: the gate
   runs BedrockMenu's village-fallback path for BOTH platforms
   (Java's definition ran plain `[console] spawn`). The fallback
   differs only where the plain command leaves the player in the
   guild world. The other three targets keep their exact per-column
   actions.
2. **Java confirm chest expiry line** ("That teleport confirmation
   has expired. Nothing happened.") is new — the old Java column
   had no gate, so there was no line to port; silence was rejected
   (a guarded door explains itself). The Bedrock failure line is
   BedrockMenu's own, verbatim.
3. **/servercommands with no argument** opens the unified
   commands_menu on both platforms (DESIGN-2.0 §1.5). Old Java got
   the all-groups chat panel; the panel survives per-group via the
   group argument. Classified here, not in the harness (the harness
   compares menu rows, not this command's framing).
4. **Screens and StatsSink**: registry + definition dispatches tap
   StatsSink as before; the ported screens' opens are not tapped
   (StatsSink is internal to the registry/definition renderers;
   BedrockMenu's screen taps were form-title/label-keyed and do not
   carry by design, §1.3).
5. **Ask/Skills/MakersMark hooks fire only on Bedrock form taps**
   (FormService). Java chest taps keep the Phase 1 behaviour
   (hint / definitions), matching both old Java columns.
6. The catalogue section of the golden fixture (the conversion
   record CatalogueModels reads) was NOT re-derived from 1.5.28 —
   only the BUTTONS/COMMANDS arrays were re-based. The catalogue
   harness's old column remains the conversion record Phase 1
   proved.
