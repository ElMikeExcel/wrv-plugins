## 4. Defects found and fixed (all during this build; none shipped)

1. **plugin.yml invalid YAML (rig boot B, first candidate run):** the mandated description sentence's `0.5.0: ` colon-space breaks an unquoted YAML scalar; Paper refused the plugin (`Invalid plugin.yml`). Fixed by single-quoting the description (parsed text identical) + a YAML-parse gate in `build.sh`.
2. **PartyLookup publication could not connect (rig boot B):** §3b's plain registration is invisible to ExcelMagicLevel because Bukkit keys services by Class object and each plugin loads its own copy of the interface (paper-api bytecode verified; MagicLevel's Phase-2 stub shared the classloader and masked it). Fixed with a bridge registration under ExcelMagicLevel's Class object alongside the specified one; contract, provider, and log line unchanged. Boot B3 proves the flip. Full evidence in SOURCE.md, interpretation call 1.
3. **Parties-enabled probe race (rig boot B):** EliteMobs 10.9.12 loads configs seconds after its onEnable; the enable-time probe read `false` under a Party.yml that says `enabled: true`, and the first build refused the mesh on it. Fixed: false-at-enable never refuses; a 30 s recheck (or a DISABLED drive result) delivers the verdict. Boot B3: mesh ON, recheck silent.
4. **Waiting-set leak:** `EmSync.markEm` now also removes the player from the EM waiting set, so an adopted waiter cannot linger as "waiting" forever.
5. **Reconstruction defects (base phase, caught against shipped bytecode):** the CFR decompile mis-rendered `PartyCombatDrops` in several places (notify loop shape, combust/splash responsible-player logic, an `n += n3` ordering in onDeath) and §4.5 of BASE-RECOVERY says "all LOW" where onDeath is in fact HIGH — the shipped bytecode arbitrated every conflict and the reconstruction follows it. Java shape fixes for byte parity: `instanceof` pattern variables vs explicit casts in four places, `HashSet` locals in `upperSet`/`enumNames`, one inlined `getEntity()`. `GeyserForms` form-input defaults are NOT %-escaped in the shipped code (labels/hints are) — first reconstruction escaped them; fixed.
6. **Build hygiene:** `build.sh` read the shipped jar from `/tmp`, which a VM restart wiped mid-task — assembly failed *after* the tests and a stale jar masked it for one cycle. The shipped jar now lives at `work/pulled-0.4.3.jar`, and `build.sh` deletes the target jar before assembling.
