- **Seam math:** 0.25 ÷ 2.5 = 0.1 (Wither/Warden ramp cap), 0.25 ÷ 1.25 = 0.2 (fight start), ÷ 1.5 mid-ramp, ÷ 1.0 = bit-exact no-op; composed take = 0.25 × vanilla at scales 1.0 / 1.25 / 1.5 / 2.0 / 2.5.

- **Boss admissions:** SONIC_BOOM and DRAGON_BREATH admitted on boss attribution only; the same causes from non-boss sources stay unadmitted.

**What the rig ran against, stated plainly:** the real ExcelBossTrial 0.3.7 jar was still scaffold-stage at build time (its DESIGN + API source exist; no candidate jar), so Boot A ran against a **contract stub**: a plugin named ExcelBossTrial exposing `com.winkreyes.excelbosstrial.api.ExcelBossTrialAPI.outgoingScaleFor(LivingEntity)` with the contract's exact semantics (PDC-stamped pressure scale, 1.0 unstamped) plus a HIGH-priority pressure handler multiplying direct boss-damager events by that scale — the two halves of the 0.3.7 contract TW composes with. The rig therefore proves **TW's side of the composition against the published contract**, not the real 0.3.7 jar; the real-jar composition proof rides the emergency window's post-install checks (see INSTALL-PACKET.md). Geyser co-loaded on the rig (the local Geyser jar reports 2.11.3-SNAPSHOT; live runs 2.12.1-b1280 — a local-copy version note, not a TW factor: TW has no Geyser interaction). Rig victims: two fake ServerPlayers — PROT = `.RylieDSunflower` (Rylie UUID, factor 0.25, debug on, `compensate.bosstrial: true`), VET = unprotected control, both 200 max HP. Evidence logs: `rig/boot-a-final.log`, `rig/boot-b-final.log` in this build folder. Both boots: **zero SEVERE**.
